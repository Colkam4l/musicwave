## 1. Context

Tauri v2 introduced first-class support for Android and iOS as build targets. Because MusicWave's backend is already Rust and the frontend is already a web app (React + TypeScript), the same codebase can be compiled into an Android APK with minimal structural changes.

This sprint adds the Android build target, adapts the UI for touch and mobile screen sizes, and produces a sideloadable APK for testing on a real Android device — comparable to apps like Bitchord or LastWave.

### Why Tauri Mobile Over a Native Kotlin App

| Factor | Tauri Mobile | Kotlin / Android Studio |
|---|---|---|
| Code reuse | 100% of Rust audio engine reused | Full rewrite required |
| Search & stream logic | Same `ytmapi-rs`, `rusty_ytdl`, `rodio` | Rewrite in Kotlin/Java |
| UI reuse | ~80% of React UI reused | Full rewrite in Jetpack Compose |
| Build toolchain | One project, two targets | Separate Android project |

### 2.2 Tasks

#### Android Setup
- [ ] **T5-1:** Install required Android toolchain on the development machine:
  ```bash
  # Install Android SDK and NDK via Android Studio or sdkmanager
  # Set environment variables:
  export ANDROID_HOME="$HOME/Android/Sdk"
  export NDK_HOME="$ANDROID_HOME/ndk/$(ls $ANDROID_HOME/ndk)"
  
  # Add Rust Android targets
  rustup target add aarch64-linux-android
  rustup target add armv7-linux-androideabi
  rustup target add i686-linux-android
  rustup target add x86_64-linux-android
  ```

  ```json
      }
    },
  ```


#### Platform Detection
- [ ] **T5-5:** Create `usePlatform.ts` hook using `@tauri-apps/plugin-os`:
  ```ts
  import { platform } from '@tauri-apps/plugin-os';
  
  export function usePlatform() {
    const [isMobile, setIsMobile] = useState(false);
    useEffect(() => {
      platform().then(p => setIsMobile(p === 'android' || p === 'ios'));
    }, []);
    return { isMobile };
  }
  ```
- [ ] **T5-6:** In `App.tsx`, use `usePlatform()` to conditionally render `<Sidebar>` (desktop) vs `<BottomNav>` (mobile).
- [ ] **T5-7:** Conditionally render `<PlayerBar>` (desktop, 72px fixed bottom) vs `<MobilePlayerBar>` (mobile, 56px, above bottom nav).

## 3. Implementation Notes

### Audio on Android
`rodio` uses CPAL as its audio backend. CPAL supports Android via AAudio (Android 8.0+). The `minSdkVersion` of 24 (Android 7.0) is the minimum for `stream-download`; raise to 26 if AAudio issues arise.

### ALSA Not Available on Android
The `alsa-lib` system dependency documented in `SETUP.md` is Linux-desktop only. On Android, CPAL/rodio uses AAudio automatically. The implementing agent must ensure `rodio` is not compiled with the ALSA feature on Android:
```toml
[target.'cfg(target_os = "linux")'.dependencies]
rodio = { version = "0.22.2", features = ["alsa"] }

[target.'cfg(target_os = "android")'.dependencies]
rodio = { version = "0.22.2", features = [] }
```

### Safe Area Insets
On Android devices with notches or gesture navigation bars, use CSS `env()` insets:
```css
.bottom-nav {
  padding-bottom: env(safe-area-inset-bottom, 0px);
}
```

### Auth on Mobile
The `headers.json` file approach does not apply to mobile. The Settings page (T4-13) already stores credentials in `~/.local/share/musicwave/settings.json` which on Android maps to the app's internal storage. This is correct — no changes needed.

### Tauri Plugin OS
Install the OS plugin to enable platform detection:
```bash
npm install @tauri-apps/plugin-os
cargo add tauri-plugin-os --manifest-path src-tauri/Cargo.toml
```
Register it in `lib.rs`:
```rust
.plugin(tauri_plugin_os::init())
```

### Code Style (from CLAUDE.md)
- Conventional commits: `feat: add android build target`, `feat: add mobile bottom nav`, `feat: add full screen player`
- Conditional compilation: use `#[cfg(target_os = "android")]` liberally to keep platform-specific code clean
